## 🚀 启动步骤

### 1. 编译项目

在项目根目录执行：

```bash
mvn clean install
```

### 2. 启动应用

启动 `dkd-admin` 模块：

```bash
cd dkd-admin
mvn spring-boot:run
```

或者运行主类：`com.dkd.DkdApplication`

### 3. 测试连接

#### 方式一：使用测试页面（推荐）

1. 用浏览器打开 `dkd-websocket/websocket-test.html`
2. 输入用户ID（如：user001）
3. 点击"连接"按钮
4. 在消息框中输入内容并发送
5. 可以打开多个浏览器窗口测试多用户场景

#### 方式二：使用 JavaScript 代码

```javascript
// 连接 WebSocket
const ws = new WebSocket('ws://localhost:8080/websocket/user001');

// 连接成功
ws.onopen = function() {
    console.log('连接成功');
    
    // 发送消息
    ws.send(JSON.stringify({
        type: 2,
        content: '你好，WebSocket！',
        senderId: 'user001'
    }));
};

// 接收消息
ws.onmessage = function(event) {
    const message = JSON.parse(event.data);
    console.log('收到消息:', message);
};
```

#### 方式三：使用 Postman/Swagger

访问 Swagger 文档：`http://localhost:8080/swagger-ui/`

找到 "WebSocket管理" 分组，可以测试以下接口：

- `POST /websocket/sendToUser` - 发送消息给指定用户
- `POST /websocket/sendToAll` - 群发消息
- `GET /websocket/onlineCount` - 获取在线人数
- `GET /websocket/onlineUsers` - 获取在线用户列表
- `GET /websocket/isOnline/{userId}` - 判断用户是否在线

## 💡 业务集成示例

### 示例1：订单完成后推送消息

```java
@Service
public class OrderServiceImpl implements IOrderService {
    
    @Autowired
    private WebSocketService webSocketService;
    
    @Override
    public void completeOrder(String orderId, String userId) {
        // 订单业务逻辑...
        
        // 推送消息给用户
        String data = JSON.toJSONString(Map.of(
            "orderId", orderId,
            "status", "completed",
            "time", LocalDateTime.now()
        ));
        
        webSocketService.sendToUser(userId, 2, "您的订单已完成", data);
    }
}
```

### 示例2：售货机状态变更通知

```java
@Service
public class VendingMachineServiceImpl implements IVendingMachineService {
    
    @Autowired
    private WebSocketService webSocketService;
    
    @Override
    public void onMachineStatusChanged(String machineId, String status) {
        // 获取关注该设备的用户列表
        List<String> userIds = getUsersByMachineId(machineId);
        
        // 推送给每个用户
        String content = String.format("设备 %s 状态变更为: %s", machineId, status);
        for (String userId : userIds) {
            webSocketService.sendToUser(userId, 2, content);
        }
    }
}
```

### 示例3：系统公告群发

```java
@Service
public class NoticeServiceImpl implements INoticeService {
    
    @Autowired
    private WebSocketService webSocketService;
    
    @Override
    public void publishNotice(String noticeContent) {
        // 保存公告到数据库...
        
        // 群发给所有在线用户
        webSocketService.sendToAll(1, noticeContent);
    }
}
```

## 🔧 配置说明

### application.yml 配置（可选）

如果需要自定义配置，可以在 `application.yml` 中添加：

```yaml
# WebSocket 配置
websocket:
  # 心跳超时时间（毫秒）
  heartbeat-timeout: 60000
  # 最大连接数
  max-connections: 10000
  # 消息缓冲区大小
  buffer-size: 8192
```

## 📝 消息类型说明

| 类型 | 值 | 说明 | 使用场景 |
|------|----|----|---------|
| 系统消息 | 1 | 系统级别的通知 | 系统公告、维护通知 |
| 业务消息 | 2 | 业务相关的消息 | 订单通知、状态更新 |
| 心跳消息 | 3 | 保持连接活跃 | 防止连接超时断开 |

## 🔐 安全建议

1. **Token 验证**：在 `WebSocketInterceptor` 中验证用户 token
2. **消息加密**：敏感消息建议加密传输
3. **频率限制**：防止消息轰炸，可以添加频率限制
4. **权限控制**：验证用户是否有权限接收特定消息

## 📊 性能优化

1. **消息队列**：高并发场景建议使用消息队列缓冲
2. **Redis 集群**：多实例部署时使用 Redis 做消息中转
3. **连接池管理**：合理设置最大连接数
4. **心跳优化**：根据网络情况调整心跳间隔

## ❓ 常见问题

### Q1: 连接失败？
- 检查防火墙设置
- 确认端口是否被占用
- 查看控制台日志

### Q2: 消息收不到？
- 确认用户ID是否正确
- 检查用户是否在线
- 查看浏览器控制台是否有错误

### Q3: 连接频繁断开？
- 实现心跳机制
- 检查网络稳定性
- 增加重连机制

### Q4: 集群部署如何处理？
- 使用 Redis 发布订阅
- 或使用 RabbitMQ/Kafka
- 参考分布式 WebSocket 方案
