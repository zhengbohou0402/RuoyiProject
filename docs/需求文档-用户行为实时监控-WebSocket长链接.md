## 一、背景与现状

### 1.1 业务背景

插码管理平台负责采集 App / H5 / 小程序端的用户行为埋点数据。运营与技术人员需要**实时**看到某个手机号**刚刚产生**的行为（页面曝光 `imp`、点击 `click`、提交 `submit` 等），用于验证埋点上报是否成功、数据是否符合预期。

### 1.2 现状问题

当前"实时监控"功能（用户行为日志页面）采用 **HTTP 3 秒轮询**模拟长链接：

```
前端每 3 秒调 GET /manage/behaviorLog/incremental?userMobile=xxx&queryTime=xxx
后端查 event_time > queryTime 的增量数据返回
```

存在的痛点：

1. **实时性差**：最快 3 秒延迟，数据到达与展示存在固定间隔。
2. **无效请求多**：无新数据时每 3 秒仍发起一次完整 HTTP 请求（"心跳"也要走 HTTP）。
3. **服务器资源浪费**：大量空轮询占用 Tomcat 线程与带宽。
4. **技术栈有现成基础未利用**：项目 `icm-websocket` 模块已具备 WebSocket 连接池、消息实体、心跳协议、握手拦截器，但**未接入任何业务场景**。

### 1.3 建设目标

将"模拟长连接（轮询）"升级为**真实 WebSocket 长链接**，实现：

- 埋点数据一旦入库，**毫秒级**推送到前端页面；
- 建立一条 TCP 长连接，替代高频轮询，降低无效请求；
- 复用并扩展 `icm-websocket` 模块，补齐业务订阅、鉴权、心跳、断线重连；
- 保留轮询作为**降级方案**，WebSocket 不可用时自动回退。

## 二、术语定义

| 术语 | 说明 |
|---|---|
| WebSocket | 基于 TCP 的全双工通信协议，一次握手建立长连接，服务端可主动推送 |
| 长链接 | 指客户端与服务端保持的长久连接（本需求特指 WebSocket 连接） |
| 心跳 | 客户端定时发送 `type=3` 消息，服务端回 `pong`，用于检测连接存活 |
| 订阅（subscribe） | 客户端按手机号订阅，服务端只向该手机号的连接推送数据 |
| 断线重连 | 网络异常导致连接断开后，前端按指数退避策略自动重连 |
| 轮询降级 | WebSocket 不可用时，前端自动回退到 3 秒 HTTP 增量轮询 |

## 三、需求描述

### 3.1 功能需求

| 编号 | 功能点 | 描述 | 优先级 |
|---|---|---|---|
| FR-1 | WebSocket 连接建立 | 前端按 `ws://host/ws/{scene}/{userMobile}?token=xxx` 建立连接 | P0 |
| FR-2 | 鉴权 | 握手时校验 token（复用登录 token），非法 token 拒绝握手 | P0 |
| FR-3 | 按手机号订阅 | 服务端记录 `userMobile → Session`，只推送该手机号的数据 | P0 |
| FR-4 | 实时推送 | 数据生成器/采集入库后，服务端主动推送该手机号的新增数据 | P0 |
| FR-5 | 心跳保活 | 客户端每 30s 发心跳 `type=3`，服务端回 `pong`；服务端 90s 未收到心跳则判定离线并关闭 | P1 |
| FR-6 | 断线重连 | 前端监听 `onclose/onerror`，1s→2s→4s→8s 指数退避自动重连 | P1 |
| FR-7 | 轮询降级 | WebSocket 连接失败时自动回退 3s HTTP 轮询，恢复后切回 | P1 |
| FR-8 | 在线状态展示 | 前端展示连接状态（连接中/已连接/已断开/重连中），后端提供在线人数/在线列表接口 | P2 |
| FR-9 | 消息格式统一 | 推送消息统一为 `WebSocketMessage` JSON 结构（type/content/data/timestamp） | P0 |

### 3.2 消息格式定义（复用现有 WebSocketMessage）

```json
{
  "type": 2,
  "senderId": "system",
  "receiverId": "13800138000",
  "content": "新增1条用户行为日志",
  "data": "[{\"userMobile\":\"13800138000\",\"eventKey\":\"click\",...}]",
  "timestamp": 1786373668000
}
```

| 字段 | 说明 |
|---|---|
| type | 1=系统消息，2=业务消息（行为数据推送），3=心跳 |
| senderId | 发送者（固定 system） |
| receiverId | 接收手机号（订阅 key） |
| content | 人类可读摘要 |
| data | JSON 数组字符串：本次推送的增量行为数据 |
| timestamp | 服务端毫秒时间戳 |

## 四、接口设计

### 4.1 WebSocket 连接地址

```
ws://127.0.0.1:8080/ws/behaviorLog/{userMobile}?token={jwt}
ws://127.0.0.1:8080/ws/behaviorTrack/{userMobile}?token={jwt}
```

- `scene`：`behaviorLog`（MySQL 实时验证数据） / `behaviorTrack`（ClickHouse 轨迹数据）
- 握手通过 `token` 参数鉴权（复用现有 `WebSocketInterceptor` 的取参逻辑）

### 4.2 服务端推送触发点

| 触发源 | 动作 |
|---|---|
| `TestDataGeneratorController` 生成器写入 `tb_real_time_data_verification` 后 | 向订阅该手机号的 `behaviorLog` 连接推送 |
| `UserBehaviorTrackGeneratorController` 生成器写入 ClickHouse 轨迹表后 | 向订阅该手机号的 `behaviorTrack` 连接推送 |
| 外部系统/定时任务写入 | 同一通道推送 |

### 4.3 辅助 HTTP 接口（现有，直接复用）

| 接口 | 说明 |
|---|---|
| `GET /websocket/onlineCount` | 在线连接数 |
| `GET /websocket/onlineUsers` | 在线用户（手机号）列表 |
| `GET /websocket/isOnline/{userId}` | 指定用户是否在线 |
| `POST /websocket/sendToUser` | 向指定用户推送（调试用） |

```
┌─────────┐  1.登录获取token             ┌──────────┐
│  前端     │ ──────────────────────────► │  后端     │
│ (Vue页面) │                             │ (Spring)  │
│          │  2. new WebSocket(          │          │
│          │     ws://.../ws/behaviorLog/│          │
│          │     {mobile}?token=xxx)     │          │
│          │ ──────────────────────────► │ 握手鉴权  │
│          │ ◄────────────────────────── │ 连接成功type=1│
│          │  3. 每30s心跳 type=3         │          │
│          │ ──────────────────────────► │ 回 pong  │
│          │ ◄────────────────────────── │ type=3   │
│          │  4. 生成器写入新数据          │ 推送type=2│
│          │ ◄────────────────────────── │ data=新数据│
│          │  5. onclose → 指数退避重连    │          │
└─────────┘                             └──────────┘
```

## 六、非功能需求

| 项 | 要求 |
|---|---|
| 并发 | 单机支撑 ≥ 500 路长连接 |
| 消息量 | 单连接每秒 ≤ 10 条推送，避免刷屏（前端可合并渲染） |
| 心跳 | 客户端 30s，服务端超时 90s |
| 兼容性 | 原生 WebSocket API，不引入额外依赖；IE 不要求支持 |
| 降级 | WebSocket 不可用时回退轮询，功能不中断 |
| 安全 | 握手 token 鉴权；`data` 中手机号前端脱敏展示 |

## 七、验收标准

1. 登录后在行为日志页面输入白名单手机号，点击"实时监控"，选择 WebSocket 模式，连接成功且状态显示"已连接"。
2. 启动数据生成器后，前端**无需刷新**即可在 1 秒内看到新增行为日志，逐条追加到顶部。
3. 断开网络/重启后端后，前端自动重连，恢复后继续接收数据不重复。
4. 停掉后端 WebSocket 端点（模拟不可用），前端自动降级为 3 秒轮询，数据仍可展示。
5. 在线人数、在线列表接口返回正确。
